# 05 — Internacionalização PT-BR / EN / ES

Data: 28/08/2026 · Branch `main`

## Arquitetura

- **Segmento interno** `app/[lang]/…` (pt/en/es) reaproveitado; as pastas internas continuam `work`, `lab`, `studio`, `services`, `contact`, `diagnostico` e os slugs de serviço em PT.
- **URLs públicas localizadas** via tabela única `src/i18n/routing.ts` (`ROUTES`): o middleware traduz público → interno (`internalizePath`) e `localizePath`/`withLocale` fazem o inverso em links, canonical, hreflang e sitemap. Nenhuma página duplicada.
- **URLs antigas / cruzadas** (`/work`, `/studio`, `/services`, `/contact`, `/en/diagnostico`, `/en/criacao-de-sites`, `/es/work`, `/es/projetos/x`, `/pt/...`) → **308 direto** para a canônica, sem cadeia. `/raio-x` e `/en/raio-x` seguem em `next.config.mjs`.
- **Layout raiz = `app/[lang]/layout.tsx`** → `<html lang>` sai do servidor (`pt-BR`/`en`/`es`), sem script de correção.
- **404**: o middleware valida a URL contra a tabela de rotas + `src/data/slugs.ts` (lista leve dos 25 slugs, conferida contra `PROJECTS` em `data/projects.ts` — divergência derruba o build) e reescreve rota desconhecida para `[lang]/[...rest]` **com status 404**. Resultado: 404 com identidade, no idioma certo, dentro do layout real (fontes, CSS, `lang`) e `noindex`.
- **Dicionários tipados** `src/i18n/{types,pt,en,es}.ts` (`Dictionary`, `getDict`). `Localized = { pt; en; es }` — `es` obrigatório em todo conteúdo (`content.ts`, `content-projects-*.ts`, `services.ts`, `case-stories.ts`, `case-extras.ts`, `studio.ts`, `work.ts`). Chave faltando = erro de TypeScript = build quebrado. Sem `any`.
- **Dados de projeto** continuam fonte única (`data/projects.ts`: ordem, numeração, total derivado, `displayType`, cadeia next). Só o texto é localizado; rótulos de UI (`displayType`, filtros, colunas, capítulos do case, peças do Aurex, "DIA n / 132") vêm do dicionário.
- **Seletor `PT EN ES`** (`components/nav/language-switch.tsx`): `<nav aria-label>` + links com `hreflang`/`lang`, `aria-current="page"` no ativo (ponto signal), alvo ≥44px, foco visível, no header desktop e no menu mobile. A troca mantém a página equivalente (`alternatesOf`). Grava cookie `milweb_locale` (1 ano); **só a raiz exata `/`** honra o cookie (307 para `/en` ou `/es`); links diretos sempre respeitam a URL. Sem modal, sem Accept-Language.
- **SEO**: `lib/seo.ts#pageMetadata` → canonical na URL do idioma + hreflang `pt-BR`/`en`/`es`/`x-default` (= PT) + `og:locale` (`pt_BR`/`en_US`/`es_419`) + title/description traduzidos. Sitemap trilíngue (111 URLs, 37 por idioma) com alternates. JSON-LD com `inLanguage` por idioma. OG/Twitter images aceitam `es`.
- **Tipografia em três idiomas**: `.t-fit` / `.t-fit-md` (globals.css) + `lib/fit.ts#fitLines` escalam a headline pela linha mais longa (`--chars`) — a headline ES do hero cabe no ultrawide e "EMPEZAR UN PROYECTO." cabe em 320px sem quebrar palavra. Overlay mobile em `100dvh` (seletor não fica sob a barra do navegador).

- Traduções EN/ES feitas por revisão editorial automatizada (subagentes) com regras de tom; vale uma leitura humana final em ES (variante neutra LatAm) antes de divulgar para esse mercado.
- `[lang]/not-found.tsx` (fallback de `notFound()` explícito) ainda cai no shell genérico do Next quando disparado pelo layout raiz dinâmico — por isso o 404 é decidido no middleware. Rota desconhecida nunca chega lá.
- Firefox/Safari físicos continuam pendentes (ver 04-report).
